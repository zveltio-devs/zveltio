# Internationalisation

Zveltio uses **Paraglide JS** (inlang). Messages compile to typed functions, so
a missing key is a build error rather than a blank label at runtime.

**Locales (9):** `en` (base), `ro`, `fr`, `de`, `es`, `it`, `pl`, `nl`, `hu`.
Configured in `packages/studio/project.inlang/settings.json`.

---

## 1. i18n is not an extension

It is a function of the **host** *and* of **each extension**. Both halves ship
their own catalogue; the host serves the union at runtime. The engine has no
i18n routes — they were removed deliberately.

The consequence that catches people: because the host serves the *union*, an
extension can render a key belonging to another extension and it will work —
right up until someone installs the borrower without the owner, at which point
the label renders as a raw key. Extensions are independently installable, so
this is a real defect, not a theoretical one. Ten extensions had it.

---

## 2. Where the messages actually are

```
packages/studio/messages/
├── core/          THE SOURCE — edit here
│   ├── en.json    (base locale, ~200 shared keys)
│   └── ro|fr|de|es|it|pl|nl|hu.json
└── en.json …      GENERATED BUNDLE — do not edit
```

**`messages/*.json` at the top level is a build artifact.** The source is
`messages/core/`. Editing the bundle works until the next build, then silently
reverts — the same trap that generated snapshots and the embedded Studio build
set.

`packages/client` has the same arrangement.

---

## 3. Who owns which key

Three legitimate sources for a key an extension page renders:

1. **Its own catalogue** — `studio/messages/{locale}.json` in the extension.
2. **A declared dependency's catalogue.**
3. **The host's shared catalogue** — `SHARED_MESSAGE_KEYS`, the `common.*`
   generic vocabulary plus the `ext.*` shared helpers, generated into
   `packages/sdk/src/validate/shared-message-keys.ts` from
   `packages/studio/messages/core/en.json`.

Anything else must be shipped by the extension itself. Otherwise it renders
correctly only on a host whose core catalogue happens to know the key — not a
property an installable extension may depend on.

`SHARED_MESSAGE_KEYS` is **generated**. Regenerate with
`bun run scripts/sync-shared-message-keys.ts`; `check:shared-keys` verifies it.

---

## 4. Prefixes

An extension's keys are namespaced by its identity, and **the prefix is not
derived from the directory path**. Deriving it from the path is wrong and was
tried. A literal "prefix uniqueness" rule is also wrong: applied strictly it
rejects 41 of 56 correctly-named extensions, because nested categories
legitimately share leading segments.

Extension catalogues travel **on the wire** — the host ships them to the client
with the page — so a key resolvable in development is resolvable in production.

---

## 5. Gates

| Gate | Enforces |
|---|---|
| `check:shared-keys` | `SHARED_MESSAGE_KEYS` matches the core catalogue |
| `ext:i18n-ownership` | Every key an extension's **Svelte** page renders is owned, depended on, or shared |
| `extension-validate` | The same check for **SDUI** schemas |
| `check-i18n-core` | Core catalogue completeness. Does **not** read the sibling repository, so its failures are always real |

`ext:i18n-ownership` has a baseline in
`quality-gates/extension-i18n-baseline.json`. Re-baseline with `--update` only
when you have genuinely fixed the ownership, never to make a red gate green.

---

## 6. Adding a string

1. Add the key to `packages/studio/messages/core/en.json` (or the extension's
   own `studio/messages/en.json`).
2. Add translations for the other eight locales, or accept the base-locale
   fallback.
3. Use it as `m['some.key']()` — never a hardcoded literal in markup.
4. If it belongs in the shared vocabulary, regenerate `SHARED_MESSAGE_KEYS`.

SDUI schemas take message keys wherever a string is accepted: the resolver tries
`m[key]()` first and falls back to the literal, so a schema stays readable and
i18n-ready at the same time.

The locale switcher is `LocaleSwitcher.svelte`; runtime state lives in
`src/lib/i18n.svelte.ts` and navigation labels in `src/lib/nav-i18n.ts`.
